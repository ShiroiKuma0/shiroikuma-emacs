# CLAUDE.md — guide for Claude Code in this repo

**shiroikuma-emacs** — 白い熊's fork of [GNU Emacs](https://github.com/emacs-mirror/emacs) `master`
(the byte-identical GitHub mirror of Savannah; C + Java + Elisp; GPL-3.0-or-later), built for
**Android** the way the SourceForge `termux/` packages are. Installed as `shiroikuma.emacs` /
**白い熊 GNU Emacs**, side-by-side with the stock `org.gnu.emacs`, and sharing Termux's user ID
(`com.termux`) so every CLI tool in the Termux prefix is reachable from Emacs.

This repo (`ShiroiKuma0/shiroikuma-emacs`) is a fork. We track upstream's **branch tip** on
`master` and layer our customizations on `custom`.

**Upstream's `AGENTS.md`** (the file this `CLAUDE.md` used to point at) states GNU Emacs's policy
against LLM-generated *contributions to Emacs*. Nothing from this repo is ever submitted upstream —
the `upstream` remote's push URL is `DISABLED` — so it does not govern work on the fork layer.
Leave `AGENTS.md` as upstream has it.

## Fork workflow — READ THIS FIRST

### Git remotes & branches

- `origin` → `git@github.com:ShiroiKuma0/shiroikuma-emacs.git` (push here).
- `upstream` → `https://github.com/emacs-mirror/emacs.git` (fetch only; its push URL is `DISABLED`).
- `master` — mirrors `upstream/master`, **fast-forward only**. No fork work here.
- `custom` — all our work, rebased onto `master` on each sync, and the GitHub default branch so the
  repo page lands on the fork.

**Upstream tracking: `git`** — `custom` is rebased onto every upstream commit, so the fork
versionName pins the upstream base: `<upstream>+<base date>.<HH-MM>.g<sha>+<BUILD_NUMBER, 3 digits>`.
See the global **`git-versioning`** skill. Why: Emacs `master` is what SourceForge builds and what
白い熊 installs; it takes hundreds of commits a month while `AC_INIT`'s `32.0.50` stands still for
the whole development cycle, so the literal alone says nothing about how current the fork is.

### Versioning & APK naming

- `BUILD_NUMBER` (in `fork.properties`) is our per-build `N`:
  `versionName = "<AC_INIT>+<YYYY-MM-DD>.<HH-MM>.g<sha8>+<NNN>"` (e.g.
  `32.0.50+2026-09-13.02-35.gf0430371+001`), `versionCode = 320050000 + N` (plain integer,
  e.g. `320050001`). Zero-padded to 3 digits **in the name only**.
- The pin is `git merge-base HEAD master` (the upstream commit our patches sit on — not our HEAD,
  not `master`'s tip) shortened to 8 chars, plus that commit's committer date **and time, in UTC**.
  It moves only on a sync.
- **`versionCode` base is the `Version-code:` trailer, not `30 × 10000`.** The manifest's
  `versionCode="30"` is a placeholder upstream deliberately never increments (to allow downgrades),
  and `320050000 × 10000` overflows `int`. `Version-code + N` is what upstream itself reserves for
  F-Droid and it sits above every stock build of this version.
- **`BUILD_NUMBER` runs MONOTONICALLY. Reset it to `1` ONLY when the `Version-code:` base itself
  moves** (i.e. upstream bumps `AC_INIT` — once per major version) — never merely because a sync
  moved the `.g<sha>` pin. An installer compares `versionCode` and nothing else; resetting `N` on a
  sync would send it *backwards*. `build-fork.sh` records `LAST_BUILT_VERSION_CODE` in
  `fork.properties` and **refuses to build** a code that does not exceed it.
- APK: `shiroikuma-emacs_<versionName>_arm64-v8a.apk`, copied to `~/tmp/` (never overwritten —
  raise `BUILD_NUMBER` instead). Upstream's own output stays in `java/` as
  `emacs-<ver>-29-arm64-v8a.apk` (the `29` is `ANDROID_MIN_SDK`, taken from the compiler name
  `aarch64-linux-android29-clang`). The versionName contains no `_` and no `~` (Debian and
  `git check-ref-format` bans, see the `git-versioning` skill).

### Build commands

```bash
# Our build: signed release APK → ~/tmp + bump BUILD_NUMBER (use this; ~20 min cold → background)
./build-fork.sh
# Build only: leave the APK in java/, no copy, no bump (toolchain proof / experiments)
./build-fork.sh --no-deliver
# Re-run ./configure (after changing configure flags or the deps)
./build-fork.sh --reconfigure
```

`build-fork.sh` does, in order: read `fork.properties` and `keystore.properties`; compute the
version; fetch the third-party ndk-build ports once into gitignored `emacs_deps/`
(`admin/download-android-deps.sh 64`, ~150 MB, network); `./autogen.sh autoconf`; `./configure`
(only when `config.status` is missing or `--reconfigure`); `make all -j$(nproc)` with the
`FORK_*` variables; copy + bump. **Never run bare `./autogen.sh`** — without the `autoconf`
argument it also installs upstream's `commit-msg` / `pre-commit` hooks into `.git/hooks`, which
would police our fork commits with GNU's ChangeLog rules.

### Toolchain

- JDK **11** at `/usr/lib/jvm/zulu11` — **JDK 11 only**. `configure.ac` compiles the Java side with
  `--release 7` (Emacs supports Android 2.2), which JDK 21 rejects outright. `build-fork.sh` sets
  `JAVA_HOME`/`PATH` itself; the host default `java` is JDK 11 too, but never rely on it.
- Android SDK at `~/android-sdk`: build-tools `37.0.0` (`aapt`, `d8`, `zipalign`, `apksigner`),
  `platforms/android-37.1/android.jar` (configure demands API 37 = CINNAMON_BUN), NDK
  `27.3.13750724` (r27: 16 KB page-size support), compiler
  `aarch64-linux-android29-clang` → one ABI, **arm64-v8a**, minSdk 29.
- Host tools: `autoconf`, `m4`, `makeinfo`, `tic`, `curl`, `git`, `shasum` (the deps script).
- No Gradle, no `local.properties`. The Android build is `java/Makefile.in` driven by the top-level
  `make all` (host Emacs → byte-compiled lisp → `cross/` NDK build of `libemacs.so` + the
  ndk-build deps → `java/` APK).
- Configure line (in `build-fork.sh`): `--with-shared-user-id=com.termux --without-android-debug
  --with-native-compilation=no` plus the full SourceForge dependency set (`gif gnutls harfbuzz jpeg
  png selinux sqlite3 tiff tree-sitter webp xml2`) from `--with-ndk-path`.

## Hard rules

- **JDK 11 only** for this repo (`/usr/lib/jvm/zulu11`). Never point `JAVAC` at JDK 21.
- **Never rename the `org.gnu.emacs` Java package** — only the installed id differs (aapt rename).
  The JNI class names are compiled into `libemacs.so`; renaming would break startup and make every
  rebase a mass-conflict.
- **One keystore for the whole `com.termux` shared-UID family** (Termux, termux-api, termux-x11,
  termux-gui, this app): `~/.android-keystores/shiroikuma-emacs-termux.jks`. Upstream's tracked
  `java/emacs.keystore` stays as upstream has it but is **no longer what signs** — `keystore.properties`
  is. Changing the key later means uninstall + restore for everything on that UID.
- **Never commit/push unprompted.** Build, deliver, and stop; 白い熊 tests. Commit + push only on
  their explicit **"Push"** = commit + `git push --force-with-lease origin custom` (rebased history;
  `master` fast-forwards with a plain push).
- `keystore.properties`, `*.jks`, `emacs_deps/`, `.scratch/` and `.claude/settings.local.json` are
  gitignored — never commit them. `CLAUDE.md` and `.claude/skills/` **are** tracked (upstream's `.*`
  ignore rule is overridden for `.claude/`).
- **Always run `adb`, `scp` and `git status`/`git diff` with `dangerouslyDisableSandbox: true`**
  (the sandbox blocks adb's server socket and invents phantom untracked dot-files at the repo root).
- **After ANY functional change, build and deliver automatically** — the global `/after-build`
  standing authorization; never wait for "build it". Every build bumps `BUILD_NUMBER`; never
  overwrite or delete an older APK, in `~/tmp/` or on the phone. Always `run_in_background`, poll,
  never abandon it: measured 2026-09-13 on this 24-core host — one-time deps download ≈ 13 min
  (SourceForge is slow), configure ≈ 2 min, full make ≈ 6 min, warm no-op rebuild ≈ 35 s.
- On new upstream commits, run the **`upstream-new-version`** skill — it presents the
  proceed-gated Android-relevant change table **before** any rebasing, then ff-merges `master`,
  rebases `custom`, keeps `BUILD_NUMBER` running, and builds the next `+NNN`.
- **Rebase grep guard** (after every sync, before building): every site that must follow the
  installed id rather than the namespace —
  `grep -n '"org\.gnu\.emacs\|getShortClassName\|getIdentifier' java/org/gnu/emacs/*.java` and
  `git diff master..custom --stat` to confirm the fork layer is exactly what we expect.
- The stale `~/git/emacs` is a **reference clone**, never this repo. `etc/NEWS` is upstream's
  changelog and is never edited; ours is the root `CHANGELOG.md`.

### CHANGELOG.md is unified — our sections on top

Upstream ships no `CHANGELOG.md` (its history is `etc/NEWS`, left untouched), so the root
`CHANGELOG.md` is ours: one section per fork release, newest first,
`## 白い熊 GNU Emacs <tag> — <YYYY-MM-DD>`, each carrying (a) our changes since the previous release
and (b) an **"Upstream since <previous base sha>"** subsection distilled from the proceed-gate table
of the `upstream-new-version` runs in between. That is the merged changelog `/publish-version`
publishes with each release; the same text goes in the GitHub release notes.
